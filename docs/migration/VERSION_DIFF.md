# VERSION_DIFF — 新旧版本差异

## 0. 先说前提：旧版二进制不存在

工作区内与目标程序有关的样本只有两个，**都是 1.21.120.0**：

```
unpacked/unpacked_Minecraft.Windows.exe                      1.21.120.0（磁盘，脱壳后重建）
Dump/Minecraft.Windows_1.21.120.0_20261027_005946.image      1.21.120.0（运行时内存镜像）
```

没有 1.21.44 的可执行文件、镜像、`.pdb`、`.map` 或结构体转储。因此**任何
“1.21.44 的 X 在 YYYY 偏移” 的说法都无法被本仓库的证据验证**。下表把这类项目一律标 UNKNOWN，
而不是沿用旧注释里的数字。

## 2. 能确认的“版本内变化”，只有这些

以下三条是**在 1.21.120 内部**用证据确认的，不涉及与 1.21.44 的对比：

1. **`.rdata` 里的指针与磁盘头基址不匹配**（2059/7454 页），说明该 exe 的 ImageBase 与
   实际运行基址不同，且重定位表已被破坏 → 静态地址只能在镜像基址下解释。
2. **`Level_getHitResult` 的旧签名在 1.21.120 匹配到 4 处**，且解出的槽号是
   `-151183361`（负数）→ 旧模式已失效，不是“偏移漂移”，是**模式本身不再唯一**。
3. **`Mob_getCurrentSwingDuration` 的旧签名 0 命中**，且 `ItemInHandRenderer` 内联了
   等价的进度计算 → 该函数在 1.21.120 已不独立存在（与“内联”假设一致，但仍属
   **观察**，不是对 1.21.44 的比对结论）。

## 3. 结论

* 版本差异的**二进制层面对照做不了**，因为缺旧版样本。这是输入缺失，不是分析失败。
* 能做的、并且已经做的：把 1.21.120 的**真值**建立起来（节表、RTTI、虚表、43 项失败清单、
  每处字节补丁的原始指令）。有了这份基线，等 1.21.44 样本到手即可逐项对照。
* 任何“从 1.21.44 迁移过来所以应该是 X”的推断，在本仓库一律视为**未验证**。
